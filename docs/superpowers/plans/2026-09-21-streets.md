# Street Import Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Import all current streets from GAR directory 77 into PostgreSQL in one request.

**Architecture:** A dedicated XML reader reads address objects and administrative hierarchy without requiring houses. A transactional store inserts streets by GAR GUID; a thin controller exposes the import service.

**Tech Stack:** Java 21, Spring Boot 4, StAX, Spring Data JPA, MapStruct, PostgreSQL.

**Spec:** User request in this conversation: street identifiers, name and city; XML directory 77; all streets in one import.

## Global Constraints

- Follow existing flat layer packages and constructor injection.
- No 1000-record sampling for streets.
- Preserve existing house import behavior.
- Existing Docker volumes require an explicit additive migration.

## Review Focus

- Streets without houses must be imported.
- Historical/inactive objects and hierarchy entries must be excluded.
- Missing ancestors, cyclic paths and non-Moscow roots must be rejected.
- Repeated imports must not duplicate streets; failed persistence must roll back.
- More than 1000 streets must be inserted in a single call.
